# 商談スケジュール（GitHub Pages + スプレッドシート）

```
[GitHub Pages: index.html] --fetch(POST)--> [Apps Script Webアプリ: Api.gs] --> [スプレッドシート「りざぶ」]
                                                                               ├ 予約ログ（A〜F + G:予約ID）
                                                                               └ 担当者マスタ
```

- 画面：りざぶ郎風の「担当者 × 時間軸」の表。ドラッグで作成・移動・伸縮、クリックで編集・削除
- データ：今までどおり「予約ログ」シートに保存（既存のシート内フォーム・表示もそのまま使える）
- 重複チェック：同じ日・同じ担当者で時間が重なる予約はサーバー側で拒否（排他ロック付き）
- 保存・移動・削除は押した瞬間に表へ反映（裏で保存し、失敗したら元に戻して理由を表示）
- 10秒ごとに「変更があったか」だけ確認し、変更があれば読み直す（1分ごとに全件も読み直す）
- 前後の月も先読みし、前回のデータはブラウザに保存して次回は開いた瞬間に表示
- Google側の一時的な不調（404・応答なし）は自動で再試行。新規登録は画面側でIDを決めるので再送しても二重登録にならない
- 時間が重なった古い予約は段をずらして全部表示
- `?demo=1` を付けて開くと本番につながず仮データで試せる（例 `…/shodan-schedule/?demo=1`）

## 1. Apps Script 側（API）

1. スプレッドシート「りざぶ」→ 拡張機能 → Apps Script を開く
2. ファイル「＋」→ スクリプト → 名前を `Api` にして、このリポジトリの `Api.gs` の中身を貼り付けて保存
   （Code.gs はそのまま。定数や関数を共有している）
3. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - デプロイ → 表示される **ウェブアプリURL**（`…/exec`）を控える

> Api.gs を修正したときは「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」で更新しないと反映されない。

## 2. GitHub 側（画面）

1. GitHub で新しいリポジトリを作成（例 `shodan-schedule`）
2. `index.html` をアップロード
3. Settings → Pages → Source「Deploy from a branch」→ `main` / `/(root)` → Save
4. 数分後 `https://<ユーザー名>.github.io/shodan-schedule/` で公開される

## 3. 使い始める

- ページを開くだけで使える（入力は不要）。`index.html` 冒頭の `DEFAULT_API_URL` にWebアプリURLが入っているため
- URLが空のときはデモモード（ブラウザ内だけの仮データ）で動く

## セキュリティについて

- **現在は合言葉なしで運用している**（`Api.gs` の `REQUIRE_TOKEN = false`）。ページのURLを知っていれば、
  社外の人でも予約の閲覧・登録・変更・削除ができる。ページURLとWebアプリURLはGitHub上で公開されている。
- 誤操作やいたずらで消えた場合は、スプレッドシートの「ファイル → 変更履歴」から戻せる。
- 合言葉で守りたくなったら：`Api.gs` の `REQUIRE_TOKEN` を `true` にして保存 → `setupApiToken` を実行して
  合言葉を発行 → デプロイを新バージョンで更新。各自は画面の「設定」で合言葉を1回入力する。
- 「アクセス：全員」が必要なのは、GitHub Pages からはGoogleのログイン情報を付けて呼べないため。
- 組織のGoogle Workspace設定で「全員」が選べない場合、この構成は使えない。その場合は同じ画面を
  Apps Script の HtmlService で配信する方式（社内アカウント限定）に切り替える。

## 既存のシート画面との関係

- 予約ログにG列「予約ID」が追加される。シート内フォームで登録した行（IDなし）は、
  Web画面が次に読み込んだときに自動でIDが振られる。
- シート内フォームからの登録は重複チェックされない（Web画面側のみ）。
